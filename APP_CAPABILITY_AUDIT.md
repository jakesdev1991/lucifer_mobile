# Lucifer Mobile capability and control audit

**Audit date:** 2026-10-26
**Scope:** active Android source configured by `composeApp/build.gradle.kts`, manifest, launcher, terminal, wallet, browser, Kai/Omni-Bridge, settings, skills, and build/documentation. This is a code review, not a device certification; the build could not be run because this environment has no Java runtime.

## Executive summary

Lucifer already has a useful set of real controls: app launching, natural-language routing, local/Termux/VM terminal execution, a Shizuku UserService destination, and an interactive Termux PTY with a floating chat companion, an EVM key store and balance lookup, public-page text retrieval, local activity logs, voice output, a Kai sandbox ping, and a user-led workflow runner with bounded task persistence. Wallet and browser panels were added, Settings now opens the wallet manager, the Kai button performs an honest health check rather than claiming to deploy, system Settings/app launch intents were added to the natural-language router, and Skills is a truthful status catalog. At the user's request, removed manifest permission declarations were restored. The 30-minute idea/project heartbeat is now available only through explicit opt-in; it reads limited public pages, can capture and transmit one still per session after runtime camera consent, and writes local Markdown drafts. Interactive browser automation and external web writes remain unimplemented.

The largest remaining gaps are safety/production readiness, not lack of imagined features: SSH now fails closed on unpinned/changed host keys, but the new known_hosts import path has not been device-tested; wallet keys have no recovery/export flow and the app does not send transactions; browser automation is intentionally unsupported; Kai's deploy/signing paths are incomplete; and Termux/VM behavior is untested on device. The heartbeat is not an exact timer—Android may defer or stop it—and neither build nor device behavior is verified.

## Changes made during this audit

1. Added a native EVM Wallet tab with explicit confirmation before key generation, balance lookup, address copy, and plain disclosure that current wallets cannot be recovered or used to send funds.
2. Added a read-only Browser tab. The fetcher now requires HTTPS, rejects embedded URL credentials, validates each URL/redirect against local/private/reserved address ranges, and follows redirects manually so each hop is checked.
3. Routed typed app-launch requests, Lucifer panel navigation, and supported Android Settings requests through `NaturalLanguageRouter` in launcher chat/bar and MainActivity terminal input. Tapping an app tile remains a direct, explicit UI action. Opening Settings never claims that Lucifer changed the protected system state.
4. Replaced the insecure VM SSH `StrictHostKeyChecking=no` path with JSch `known_hosts` plus strict checking, host/port validation, and a Settings field for verified host-key lines. Removed the hardcoded private VM/knowledge-server address; the saved knowledge-server URL now loads at startup.
5. Replaced Settings' no-op “Connect Solana/ETH” controls with one real “Manage EVM Wallets” entry point. Replaced the no-op “Deploy Kai Sandbox” control with a real “Check Kai Sandbox” ping and visible status.
6. Removed skills switches that only changed local display state; replaced them with status/limitation labels.
7. Replaced the legacy command-capable heartbeat with a constrained idea/project session engine. A user must start it from the Heartbeat tab; it shows an ongoing notification with Stop, fetches only two public HTTPS trend pages, asks the model to self-score/select, and saves Markdown artifacts plus JSONL state in app-private storage. No model-generated command or external write is executed. An opted-in service attempts to resume after reboot in text-only mode.
8. Restored the previously removed camera, external-storage, local-network, Bluetooth, NFC, biometric, boot-receiver, wake-lock, network-state, foreground-service, and notification manifest declarations at the user's request. Added camera foreground-service typing and runtime camera/notification consent. When enabled, one still per session is sent to NVIDIA's multimodal Nemotron API and not persisted locally. Browser automation remains unimplemented; external writes still require a future review flow.
9. Added Shizuku API/provider and AIDL build support, a Shizuku status/request flow, Shizuku and Permission Manager X launch actions, and an explicit SHIZUKU terminal destination backed by a bounded UserService command runner. Commands still go through natural-language understanding; non-read-only commands require the existing per-action confirmation. Lucifer observes/uses the Shizuku grant but never changes Permission Manager X permissions. No build or device test has run.
10. Added a persistent interactive Termux `tmux` PTY launch, an explicit broad CLI toolkit installer, a draggable floating chat service with Stop notification, natural-language command routing/confirmation and pane capture, and Android Linux Terminal launch with the same overlay. The AOSP/Google AVF guest has no public external shell API; VM SSH remains available only after the user enables guest SSH and Terminal-app port forwarding. Termux result callbacks were corrected to use the documented `com.termux.RUN_COMMAND_PENDING_INTENT` extra. SSH user/port are configurable for the forwarded guest port. None of these additions has been compiled or device-tested.
11. Added local-only Termux static-site and Python stdlib API starter previews, launched in separate tmux sessions bound to loopback with health checks and a stop action. Starter files are not overwritten on subsequent staging. Public deployment, domains, HTTPS, and remote-server management are not implemented.
12. Disabled the legacy OmniBridge raw-hash wallet signing operation and made key retrieval/hash signing private to the wallet implementation. That legacy payload had no transaction fields required to enforce the selected bounded-spending policy. No policy values or spend capability are enabled yet.
13. Added a local-only USDC checkout prototype reflecting the user's selections (crypto plus card/bank sources, Arbitrum USDC settlement, separate receiver). It discloses that no payment occurs; it has no wallet connection, quote provider, processor, configured recipient, or live invoice flow. Both demo POST routes return HTTP 503 with an explicit disabled message. It is a UX/demo slice, not a payment integration.
14. Added four reusable workflow blueprints and a Work tab with bounded atomic task persistence, explicit one-step starts, existing terminal confirmation boundaries, manual observation entry, bounded result redaction, model reflection/replanning, pause/retry, and user-confirmed completion. The runner does not loop in the background or launch other panels; task goals and observations may be sent to NVIDIA and stored workflow text is unencrypted. It is source-only and not compiled/device-tested.
15. Added `SHIZUKU_ANDROID_ACCESS.md`, exposed the implementation facts in Settings/Skills and Android-specific assistant context, distinguished UserService from Binder-wrapper integration, and blocked recognizable direct PM/AppOps permission mutations targeting Permission Manager X. This targeted guard is not a general shell sandbox; no direct PackageManager/AppOps Binder feature was added.

## Prioritized follow-up work

### P0 — before relying on this app for sensitive use

- **Test the SSH pinning path.** VM SSH now uses `StrictHostKeyChecking=yes` and an app-private known_hosts entry. Device-test first use, a matching key, changed key rejection, non-default host/port formatting, and user-supplied fingerprint verification before relying on it.
- **Make VM setup clearer.** Device-test host/port validation and ensure the confirmation view presents the username, exact host/port, and visible pin status before execution.
- **Wallet recovery and signing.** Design a tested recovery phrase/export backed by explicit user authentication and secure backup guidance before any wallet can reasonably receive funds. Add chain-ID/network validation, transaction construction, preview, fee/recipient checks, and explicit signing/broadcast confirmation before any send API. Do not expose Kai-generated private keys in UI/logs.
- **Runtime/device verification.** Test Termux callbacks, strict VM SSH pinning (new/matching/changed keys and non-22 ports), Shizuku bind/permission callback/UserService `id` and timeout as shell and root, Android Settings intents, wallet persistence across process restart/reinstall, browser redirect/private-host/cookie isolation, camera FGS permission/indicator/still capture and NVIDIA image request, heartbeat notification Stop/process restart/boot-resume behavior, workflow plan/observation/reflection/recovery and confirmation boundaries, LLM failure handling, artifact persistence, and battery/Android background limits.
- **Build/CI.** Provide JDK 17 + Android SDK in CI and run `:composeApp:assembleDebug`, lint, unit tests, and manifest checks. This workspace has no Java (`./gradlew` exits 127), so no Kotlin compile/test result is claimed here.

### P1 — expand useful, safe control

- **USDC checkout is a requirement, not an implemented feature.** User selected crypto plus card/bank payment sources, Arbitrum USDC settlement, and a separate receiving wallet. Design distinct adapters: (1) payer-wallet crypto checkout with a quoted, explicitly supported swap route into the pinned official USDC token on Arbitrum, where the payer signs; and (2) a hosted fiat checkout provider that performs its own KYC/risk checks and supports settlement to the chosen wallet. No generic “any currency” promise: enumerate supported chains/assets, show fees, slippage and quote expiry, and verify paid state from trusted provider webhooks/on-chain transfers with invoice IDs and replay/idempotency protection. Keep outgoing bot-wallet transfers disabled until recovery and an independently enforced spending policy exist. Provider/contract/account selection remains open.
- Implement the user's requested browser automation behind a domain allowlist and visible action preview. The user selected confirmation before any external submission/post/message/purchase; build a review queue for those writes rather than allowing silent submission. Keep authentication and session data scoped and user-controlled.
- Implement durable skills/settings state only when each switch actually gates the named subsystem. The current status catalog avoids pretending that a visual toggle controls code.
- Add one reusable action-confirmation model for all non-idempotent integrations (not just shell). Show exact target, data being sent, and irreversible effects.
- The user requested camera access, browser automation, and writing capability in heartbeat sessions. Local Markdown writing and camera still capture with an explicit runtime grant are implemented; browser interaction, external website writes, and user-selected shared-storage export remain unimplemented. Add them with scoped storage/SAF and a review queue requiring confirmation before external submissions, posts, messages, purchases, shell commands, or other high-impact writes. Do not treat manifest declarations as consent.
- Add structured, redactable audit logs and retention controls. Existing activity/terminal history is local but not a complete provenance or semantic-memory system.

### P2 — architectural cleanup

- `composeApp/build.gradle.kts` applies Android application + Kotlin Android plugins and explicitly compiles `src/androidMain/kotlin`; the `commonMain` tree and `androidMain/kotlin.backup` contain stale/uncompiled references and prototype screens. Reconcile or remove the misleading dormant architecture only after confirming no downstream tooling consumes it.
- Remove or clearly label Omni-Bridge modules whose ONNX/BLAKE3/Wasmtime/embedding/mmap work is marked “in production” but has no implementation. Avoid advertising these as available skills.
- Keep README and the audit ledger synchronized as integrations change; verify native build/deploy scripts and legacy package prerequisites before advertising them.

## Security and verification notes

- Command confirmation reduces accidental execution but does not make arbitrary shell commands safe; a user who confirms `rm`, `sudo`, `curl`, or other commands authorizes their effects on the selected target. VM confirmations now show the configured SSH destination details.
- Browser host checks resolve DNS before connecting and repeat for redirects, but the HTTP stack may resolve a hostname again when opening its connection. Treat this as defense-in-depth, not a complete SSRF/DNS-rebinding boundary.
- Android Keystore encryption protects persisted key material at rest under the app's trust model; it is not a recovery phrase, hardware wallet, or protection against a compromised/unlocked app process.
- NVIDIA API secrets were removed from current source in earlier work, but historical repository exposure remains: revoke/rotate any credential ever committed.
- XML parse checks and `git diff --check` pass after the changes. Gradle/Kotlin compilation, lint, unit tests, and physical-device behavior remain unverified because Java/JDK and a connected device are unavailable in this environment.
