# Lucifer Mobile

Lucifer Mobile is an Android launcher and assistant with natural-language chat, a multi-target terminal, local activity logs, voice output, and limited device/web controls. The actively configured app is Android-only: `composeApp/build.gradle.kts` applies the Android application and Kotlin Android plugins and compiles `src/androidMain/kotlin`.

## What currently works

- **Natural-language-first input:** launcher chat/bar and the MainActivity terminal route text before action. Requests can be answered, clarified, routed to LOCAL/TERMUX/VM, used to open an installed app, or used to open a supported Android Settings page. Tapping an app tile remains an explicit direct launch.
- **Terminal:** LOCAL app shell, Termux commands, configured VM SSH, Shizuku UserService, and a Termux interactive PTY mode. Termux can run a persistent tmux session with Lucifer's draggable chat overlay; chat commands enter that same session after any required confirmation, and the visible pane can be inspected. In TERMUX, **STAGE STATIC** and **STAGE API** create starter projects under `~/lucifer-sites/` and launch loopback-only previews on ports 8765/8766; **STOP PREVIEWS** stops them. These are local demos, not public deployments. Existing site files are preserved instead of overwritten. The optional toolkit installer is explicit and runs visibly in Termux. Non-read-only commands require confirmation; confirmation is not a sandbox.
- **Android control:** open Wi-Fi, Bluetooth, location, display, sound, notifications, battery, app, or Lucifer permission settings. Android keeps protected toggles user-controlled; Lucifer opens the relevant settings screen rather than claiming to change the switch.
- **Shizuku bridge:** checks server/grant/version and reports whether the authorized process is ADB shell (UID 2000) or root (UID 0), then binds Lucifer's bounded AIDL UserService. Settings offers a validated, read-only package/permission/AppOps report; it does not edit grants or upload the output. This build currently executes shell commands rather than direct system-service Binder wrappers; each platform operation remains version/SELinux dependent. Lucifer will not change Permission Manager X grants; recognizable PM/AppOps permission mutations targeting PMX are blocked. See [SHIZUKU_ANDROID_ACCESS.md](SHIZUKU_ANDROID_ACCESS.md).
- **Pixel/Android diagnostics:** local snapshot identifies Pixel 8a (`akita`) when the running build reports it, and reads OS/build, process/power, Usage Access-for-Lucifer, and active VPN status. It does not read other-app usage history or capture network traffic. See [PIXEL8A_ANDROID_SYSTEMS.md](PIXEL8A_ANDROID_SYSTEMS.md).
- **Wallet panel:** create EVM addresses, list/copy addresses, and query native-token balances on Ethereum, Arbitrum, Optimism, Base, or Polygon. Private-key material is stored encrypted with Android Keystore-backed AES-GCM. Legacy raw-hash signing requests are rejected; there is no configured spending policy or transaction-send flow.
- **Read-only browser panel:** fetch HTTPS pages and extract text. It does not execute JavaScript, click, type, sign in, submit forms, or purchase; local/private/reserved hosts are rejected as defense-in-depth.
- **Surface awareness (implemented; classifier and answers host-verified, not compiled or device-tested):** Lucifer knows which interface he is speaking through — launcher chat, control-app chat, terminal tab, the Termux overlay, the VM overlay, the workflow runner, the recovery panel — and what that interface can and cannot do. Questions about himself are answered deterministically from compiled surface data plus live device state (network switch, model key, Termux permission, VM host-key pin, Shizuku presence), never by the model guessing. Every other turn carries the surface block in its prompt, so "here" is grounded. The answer always states the boundary: he is told which surface he is on and does not see the screen. `tools/surface-core/audit_surfaces.py --check` fails if a reasoning call site does not declare its surface. See [SURFACE_AWARENESS.md](SURFACE_AWARENESS.md).
- **Privacy switch and egress ledger (implemented; rules host-verified, panel not device-tested):** every outbound request is authorised by `privacy/NetworkGuard` immediately before its socket opens, and `privacy/EgressHttp` is the only place in the app that can open one. Settings → Privacy offers **GO DARK · NETWORK OFF**, which writes `files/config/network_enabled.txt` and makes every non-local destination refuse before connecting while Termux, the VM bridge, the memory MCP and the Omega knowledge server keep working. Each attempt is recorded in a bounded local ledger of host and path only — never a query string — with the trigger, the class (MODEL/VISION/SEARCH/PAGE/RPC/CODE/LOCAL), and whether a person asked. `python3 tools/privacy-core/audit_egress.py --check` fails if a socket is opened outside `EgressHttp` or a site skips the guard (currently 9 gated call sites, 1 socket owner, 0 outside the gate). This is transparency and a kill switch, **not anonymity**: it does not touch the radio, the network path, or attestation, and Lucifer implements no mock location, no identifier spoofing and no VPN. See [PRIVACY_AND_IDENTITY.md](PRIVACY_AND_IDENTITY.md) and the generated [EGRESS_AUDIT.md](EGRESS_AUDIT.md).
- **Transport · Tor for his own traffic (implemented; rules host-verified, no circuit run here):** Settings → Privacy has a TRANSPORT switch. On `VIA TOR`, every remote request Lucifer makes — prompts, page fetches, searches, RPC, corpus sync, audit-vault calls — goes through a SOCKS5 proxy (Orbot on `127.0.0.1:9050` by default) with the **hostname handed to the proxy unresolved**, so this phone never performs the DNS lookup that would otherwise hand every destination to the resolver while the proxy looked anonymous. TLS is layered over the tunnel with hostname verification, `.onion` addresses work only in this mode, and if the proxy stops answering requests are **refused rather than sent directly** — there is no silent fallback. `TEST CIRCUIT` asks Tor Project whether the exit is a Tor node and reports `IN CIRCUIT` / `NOT IN CIRCUIT` / `UNVERIFIED` rather than assuming. There is deliberately **no `VpnService`**: device-wide tunnelling belongs to Orbot's VPN mode or WireGuard, and Lucifer only reports whether one is active. Tor changes the network path, not who you are to the services you already use. See [NETWORK_AND_TOR.md](NETWORK_AND_TOR.md).
- **Play-stack detection (implemented; classifier host-verified, panel not device-tested):** Settings → Privacy reports whether the device runs Google Play Services, official microG, ReVanced GmsCore, or nothing, with the integrity/push/location consequence of each. Detection does not trust the package name, because official microG installs as `com.google.android.gms`; it scores label, version shape, installer and Play Store identity, needs two signals before naming microG, and shows `UNKNOWN` with its evidence otherwise. Lucifer itself remains degoogled by policy, and `audit_egress.py --check` fails on any GMS/Firebase/play-services dependency or import. See [MICROG_AND_PLAY_SERVICES.md](MICROG_AND_PLAY_SERVICES.md).
- **Play-privilege reporting (implemented; classifier host-verified, panel not device-tested):** the same probe reads `FLAG_SYSTEM` on the GMS package and reports whether Play Services is a *system* app — the property that decides whether it has reach you cannot revoke — or an ordinary sandboxed app. Settings → Privacy prints `PRIVILEGE: SYSTEM APP …` / `PRIVILEGE: ordinary app …`. A FLOSS Play stack flashed into `/system/priv-app` is reported as equally privileged. See [TEXTNOW_WITHOUT_ROOT.md](TEXTNOW_WITHOUT_ROOT.md) for the VoIP decision this answers.
- **Memory and skills panels:** maintain compact, redacted local memories in app-private SQLite with importance-ranked retrieval (no age-based expiry; 2 GiB disk cap), retrieve them before model calls, and retain local/static recall when offline. Automatic low-value compaction/offload to the separately selected summary-only long-term server is not yet implemented; local entries remain until manually cleared or the database reaches its cap. Optional private Drive retrieval remains read-only and separate, served by a native C++ Termux MCP service with llama.cpp Q4 embeddings plus BM25 fallback. Termux:Boot + runit supports best-effort automatic restart. Python is test-only, not part of the memory runtime. See [the MCP setup, local-memory, and data-flow notes](mcp/DRIVE_MEMORY_MCP.md).
- **Workflow blueprints and runner (implemented, not yet compiled/device-tested):** choose a software-change, research, local-site, authorization-gated bug bounty, formal-verification, Pixel 8a system/permission audit, or recover-from-a-failure recipe; Lucifer plans, runs one user-started terminal/chat step or accepts a user-entered observation from another panel, reflects, and proposes at most one next step. The task target is fixed, non-read-only terminal commands still use the existing exact-command confirmation, and completion requires a separate user action. There is no background workflow loop. Task goals and observations may be sent to the configured NVIDIA model; saved task text is in app-private storage but is not encrypted. Common token/password patterns are redacted from captured output, not every possible secret format. See [WORKFLOW_BLUEPRINTS.md](WORKFLOW_BLUEPRINTS.md) and the [bug bounty workflow and its current limits](BUG_BOUNTY_WORKFLOW.md).
- **Recovery + self-learning loop (implemented; pure logic host-verified, panel not device-tested):** every finished command is classified. A failure becomes a recovery episode: Lucifer runs a **fixed read-only probe catalog** on the failing target (LOCAL, Termux, pinned VM, or Shizuku) to inspect the machine, can ask the configured model for a diagnosis with divergent hypotheses (deterministic heuristic fallback without a model), and can **research public web sources read-only** (DuckDuckGo HTML plus a couple of result pages, `robots.txt`-aware, rate-limited, page-budgeted, with `[S1]` citations). Next moves are ranked from the per-class playbook *and* from locally recorded outcomes, so a tactic that has failed is not repeated and one that worked is promoted. Read-only moves run directly; anything that changes the system is still routed through the existing natural-language router and exact-command confirmation. See [RESILIENCE.md](RESILIENCE.md).
- **Agent ecosystem + the General (implemented; pure logic host-verified, panel/service not device-tested):** `soul.md`, `heartbeat.md`, and one `agent-class.md` per agent are now the source of truth and all are user-editable in the **Agents** tab. Session prompts are composed from those files instead of a hard-coded string, and every soul read (chat, heartbeat, cognitive router) goes through one validated store. Agents can be written by the user or composed by Lucifer from a goal, and the roster is capped at 24. A user-started foreground **tactician** runs one bounded pass every ~60 minutes over signals the app already records — package changes, commands and outcomes, recovery lessons, workflow status, heartbeat sessions, camera *use* metadata, model calls, prompt edits, agent runs — and proposes structural fixes it never executes: exhausted failure signatures, missing instrumentation, unused or overlapping agents, heartbeat drift, camera consent with no camera use, stalled workflows, budget pressure. Proposals are approval-gated; approving a skill/agent proposal writes a real `agent-class.md`. Model reasoning is budgeted (40 calls/day, 20-minute spacing, quiet hours 23:00–07:00) and detector findings survive a failed or garbage model reply. See [AGENTS.md](AGENTS.md).
- **Morningstar interface (implemented; geometry host-verified, UI not compiled or device-tested):** the launcher, panels, and terminal share one design language — true-black OLED canvas, glass panels cut at 45° instead of rounded corners, Cinzel/Inter/JetBrains Mono bundled fonts with no system fallbacks, crimson reserved for interactive and focal elements, and a sigil clock that doubles as a battery/memory/load wheel. The home screen is deliberately not a grid: masthead, one command bar, a collapsible output pane, an asymmetric text-only app drawer with a bloom on favourites, and a five-circle dock. Panels enter on a heavy downward "Fall" curve, long-press spreads a crimson pulse outline, and clearing the ledger or closing burns the content into embers. Backdrop blur needs API 31 and this build ships `minSdk 28`, so glass is faked with layered gradients and a 1 px inner hairline rather than blurred; that limitation is deliberate, not an oversight. See [MORNINGSTAR.md](MORNINGSTAR.md).
- **Privilege and Lucifer's world (implemented; core host-verified, adapters uncompiled):** two different backends, kept separate on purpose. **Shizuku** supplies a shell — ADB shell (UID 2000) or root — for `pm`/`cmd`/`am` work and stops when the phone reboots; **Dhizuku** supplies a borrowed *device-owner* identity over Binder, survives reboots, and cannot run shell text at all. A **World** tab turns either into named actions: create a managed profile as Lucifer's room, wake or freeze it (`am start-user` / `am stop-user -f`), launch apps inside it through `CrossProfileApps`, start the Android VM host there, and make owner calls (hide, suspend, grant/deny) through `DevicePolicyManager`. Every state-changing action shows its literal command and waits for you; nothing in this layer is reachable from chat, an agent, a workflow or a background pass. Lucifer will not hide, suspend or uninstall himself, Shizuku, Dhizuku, or Permission Manager X, and PMX's own grants stay read-only. If Lucifer is provisioned as device owner (`dpm set-device-owner com.lucifer.mobile/.privilege.LuciferDeviceAdmin`) the profile route needs no third-party app and no hidden API. See [PRIVILEGE_AND_WORLD.md](PRIVILEGE_AND_WORLD.md).
- **Lean verification server (implemented; control plane and runtime host-verified, service/panel not device-tested):** Lucifer hosts a **Lean 4 proof-checking MCP server** in his world work profile. The phone is the control plane — endpoint, keys, scopes, quota, metering, the tunnel — and every elaboration happens on a remote Lean host, because a work profile cannot build mathlib. Six tools and no shell: `lean.check` (1 credit), `lean.sorry_scan` (2), `lean.axioms` (3), `lean.build` (5), `lean.gates` (6), `lean.verify` (8), each with a wall-clock ceiling. `lean.gates` is the point: kernel soundness is the floor, not the audit, so it runs the four `audit-vault` gates — zero `sorry`/`admit`/`native_decide`/`axiom`, no vacuous or degenerate statement, no name asserting more than it proves, and declaration parity — and returns suspects with line numbers. It never reports "validated"; the best outcome is `GATES CLEAN — human validation still required`. `tools/call` passes four gates in order — key and scope, tool allowlist, parameter planning with a source screen for `#eval`/`unsafe`/`run_cmd`/`@[extern]`, then quota — so a refusal is free and never reaches the host. Keys are `lvs_<id>_<secret>` with only their SHA-256 stored, scopes `READ`/`VERIFY`/`BUILD`/`ADMIN`, and plans from `FREE` (50 credits) to `ENTERPRISE` (200 000 at $0.008); Lucifer's own `INTERNAL` key is unbounded, callable from his own process without a token, and is what he uses for bounties, workflow checks and theory-of-everything proofs. Work is charged after it happens and never when no host ran it. The socket binds `127.0.0.1:8791`; publishing it needs a Cloudflare or SSH reverse tunnel whose token is read from a mode-600 file and whose command the owner confirms, like every other state-changing action here. Backends are pluggable behind one executor seam: an optional signed HTTP job API when linked and healthy, the Debian VM over SSH otherwise — a failed proof is never retried on the other backend, only an outage is. `audit-vault` itself is a private audit workspace, not a job runner, and nothing in it is ever sent to the phone or the network. See [LEAN_VERIFICATION.md](LEAN_VERIFICATION.md) and [AUDIT_VAULT.md](AUDIT_VAULT.md).
- **Credential storage:** user-provided NVIDIA, VM, and Drive-memory MCP bearer secrets are stored encrypted with Android Keystore, not embedded in the current source. Termux's separate MCP token is kept in a mode-600 user config file.
- **Settings storage (implemented; audit-enforced, not compiled):** every `files/config/*` value has one name and one writer in `config/AppConfig.kt`. Writes are atomic (`AtomicFile`: write a sibling, rename over the original) so a process death mid-save cannot leave a half-written hostname or port for the SSH path to trust. `tools/config-core/audit_config.py --check` fails if any other file spells a `config/` path itself or writes one directly.

### Important limitations

- **Do not fund generated wallets.** There is no recovery phrase/key export, configured spending policy, or transaction-send flow. Raw transaction signing is disabled because the legacy bridge receives only a hash and address and cannot validate recipient, value, fees, or limits. If the device or encrypted app data is lost, those wallets cannot be recovered.
- VM SSH now requires JSch `StrictHostKeyChecking=yes` and a saved `known_hosts` entry. Host-key setup has not yet been verified on a device; independently verify the fingerprint before saving it.
- Termux requires Termux itself, `allow-external-apps=true`, and Lucifer's Termux run-command permission. The interactive mode additionally requires Android's **Display over other apps** permission and installs/uses `tmux`; the optional curated toolkit is installed only after a visible confirmation and package installs are displayed in Termux. Lucifer's small floating chat can submit a single command line to the same tmux PTY, refresh a pane snapshot, or poll it every four seconds when **LIVE** is enabled. When you ask about terminal help, up to 2 KB of current output may be sent to the configured assistant service.
- Android's built-in Linux Terminal is an AVF-managed Debian VM and has no documented third-party shell-control API. Lucifer can launch it with the same floating chat, but direct command control requires enabling `openssh-server` in the guest, configuring Terminal's port-forwarding UI, and entering the forwarded host/port/user/password plus independently verified SSH host key in Settings. Without that bridge, the overlay is chat-only over that app; Lucifer does not bypass AVF or use hidden system APIs.
- VM commands require the configured hostname/IP, reachable SSH on port 8022 as user `droid`, the SSH password saved in Settings, and a `known_hosts` entry whose SHA-256 fingerprint you independently verified. Lucifer refuses VM execution when no matching host-key entry is present.
- **On-device Lean verification is implemented but unvalidated.** In Settings, prepare the public Omega Theory source first; review its exact commit SHA and pinned `lean-toolchain`; then explicitly confirm before audit scripts and `lake build ToE` run in a dedicated Debian tmux job. Status and logs persist in the guest and can be refreshed/stopped. The local VM host must be `127.0.0.1` or `localhost` through the configured forwarded SSH port. Preparation has a 10-minute timeout; verification has a two-hour deadline, and a timeout is never a pass. Requires Git, tmux, coreutils `timeout`, Python 3, elan/Lean/Lake, and network/storage for pinned dependencies; after confirmation, elan/Lake may download the pinned compiler/dependencies, but Lucifer does not invoke apt. This verifies that repository revision only—not the app's non-identical bundled corpus, physical interpretations, or an Android release. No app build or VM execution has yet validated the integration.
- Kai sandbox deployment is not implemented. Settings offers a ping/health check only; bridge operations depend on an installed Kai package and external sandbox files and remain incomplete.
- Camera and its foreground-service type are connected to the opt-in heartbeat. Notification permission is requested before starting on Android 13+; camera permission is requested only when the user separately enables camera context. Storage, Bluetooth, NFC, biometric, and local-network declarations are restored, but those integrations are not yet connected; declarations alone do not grant runtime access.
- **Heartbeat:** an explicit opt-in control in the Heartbeat tab starts a visible foreground service, runs one idea/project session immediately, then waits about 30 minutes after each completed session. The model assigns its own importance score, continues or parks backlog work, reads limited public GitHub Trending/Hacker News pages, and writes Markdown drafts plus a session ledger under private `files/heartbeat/`. A configured NVIDIA API key is required. Camera use is optional and enabled separately in the Heartbeat tab. When enabled and CAMERA consent is granted, the service captures one still per session and sends it with public trend text to NVIDIA's multimodal Nemotron endpoint; the image is not saved by Lucifer. The service never executes generated commands, posts, submits forms, deploys, or writes outside that private directory. Android may defer or stop background work, so cadence is approximate. An opted-in service attempts to resume after reboot or a service restart in text-only mode; camera must be re-enabled from the foreground app. API usage may incur cost.
- No public website deployment or real USDC checkout is implemented. **PAYMENT DEMO** creates a clearly labeled local-only prototype; quote and checkout requests return disabled responses and cannot move money. The requested payment direction is crypto plus card/bank checkout, with USDC settling on Arbitrum into a separate receiving wallet; provider, supported source assets, wallet recovery, and payment verification are still to be designed. Do not use the current generated wallets for funds. Browser automation and web writes are not implemented; the Browser tab and heartbeat research are read-only. Generated work is local draft writing, not writing to shared Documents or publishing to a website.
- Browser URL/DNS checks are not a hardened defense against DNS rebinding. Treat fetched web content as untrusted.
- **Surface-awareness limits:** the descriptions are compiled facts about this app, not a live UI inspection — he knows the surface identifier and its documented behaviour, not what is drawn on screen. The classifier is conservative on purpose (a false interception would hijack ordinary questions), so some interface questions fall through to the model, which then has the surface block but may still phrase things loosely. The Compose layers have not been compiled by Gradle.
- **Play-privilege limits:** the privilege line reflects package placement, not runtime behaviour — a system GMS is flagged, but what it actually does is outside Lucifer's reach. Lucifer cannot contain or sandbox a system Play Services, cannot install microG (that needs signature spoofing, therefore a ROM, therefore root-adjacent flashing), and cannot make a Play-Integrity-gated app such as TextNow run on a de-googled device.
- **Play-stack limits:** the probe is a heuristic over package metadata, not proof of what a Play implementation will do; two signals are required before naming microG, but a real device can still land in `UNKNOWN`. Choosing a Play stack does not change Lucifer's own behaviour (zero Google dependencies) and does not change what Google sees on the network path — microG's push still checks in with `android.clients.google.com` and holds a socket to `mtalk.google.com`.
- **Privacy limits:** inside this app the guard is structural — `privacy/EgressHttp` and `net/SocketDialer` own every socket, the audit fails if a third file opens one, and `EgressHttp.open()` (the `HttpURLConnection` door) is restricted to the two loopback clients so a remote request cannot bypass the transport decision. It still cannot police code it does not own: a third-party dependency, a WebView and the OS itself can open sockets without asking, so the ledger records Lucifer's decisions, not the kernel's. The switch does not stop the OS, other apps, or carrier telemetry, and the ledger records Lucifer's decisions rather than proving what the kernel did. Mislabelling is possible if a caller passes a wrong expectation. Neither `NetworkGuard.kt` nor the Privacy card has been compiled by Gradle or run on a device. Lucifer will not spoof an IMEI, mock a location it never reads, or pretend microG changes anything: the APK ships zero Google dependencies. `hiddenapibypass`, Dhizuku and Shizuku remain in the APK and make the device *more* recognisable, not less.
- **Tactician limits:** it sees event summaries and metadata Lucifer already stores — never message bodies, browsing history, or another app's private data. It has no execution path, cannot edit prompts or change permissions on its own, and cannot spend money or contact anyone. Background passes need the ongoing notification and may be delayed by Android. Observations and proposals are unencrypted in app-private storage (800 observations / 40 proposals, redacted). The Compose Agents panel and `TacticianService` have not been compiled by Gradle or run on a device.
- **Recovery loop limits:** there is no background recovery daemon and no autonomous repair. Probes are a fixed read-only catalog (exact-match enforced) and can only observe; diagnoses are point-in-time and may be wrong; web excerpts are untrusted third-party text. Research never logs in, posts, submits forms, or purchases. Lessons are stored unencrypted in app-private storage (bounded to 400 records / 256 KB) and contain redacted error text only. The Compose Recover panel and the Android adapters have not been compiled by Gradle or run on a device.

## Reference skill library

The Skills tab keeps implemented/partial controls in a separate operational registry and adds a searchable library of 100 reference-only skills across ten packs. Guidance entries show prerequisites, safety boundaries, verification notes, and source links; they are not executable tools and cannot grant authorization. Retrieval is schema-validated and bounded before it can ground assistant/workflow prompts. ## Learned skills

Separately from the reference library, Lucifer keeps a short list of habits learned from his own turns: a
correction you made, a question you had to ask twice, and a recovery tactic that fixed a failing command.
It is always on, local, capped (64 skills / one file), and injected as *habits, not permissions* — a
learned line can change how he answers but cannot grant a tool, a confirmation or a capability. Settings →
**LEARNED SKILLS** pauses it or forgets everything; the Skills tab shows the counts. The rules are mirrored
in `tools/synth-core/spec_check.py` (128 checks) and `tools/synth-core/SkillSynthCoreTests.kt`. See
[SKILL_SYNTHESIS.md](SKILL_SYNTHESIS.md).

## Using chat and the terminal

Open **CHAT** from the launcher or type into the launcher bar. The request is understood before routing. Examples:

- “Show disk space on my VM”
- “List files in Termux”
- “Open Chrome”
- “Open wallet,” “Open the browser panel,” or “Open workflows”
- “Open Bluetooth settings” (Android will ask you to make protected changes there)
- “What is entropy?”
- “Run `git status` on the VM”

Choose LOCAL, TERMUX, VM, or SHIZUKU as the default destination, or name a target in the request. Familiar read-only diagnostics can run directly. Other terminal commands display the exact command and target and wait for explicit confirmation. Questions and hypotheticals are chat, not shell commands. In the Terminal tab, select TERMUX and tap **OPEN PTY + CHAT** for a persistent interactive tmux shell with the floating companion; **INSTALL TOOLKIT** offers the curated Termux package set with a package-install confirmation first. **STAGE STATIC** and **STAGE API** create a starter site and a read-only sample API under Termux home and run each only on `127.0.0.1`; use the on-device browser at the displayed URL to preview. **PAYMENT DEMO** runs a no-money prototype for the selected Arbitrum USDC + crypto/card-bank direction; it has no wallet connection, quote provider, card processor, recipient address, or payment endpoint enabled. **STOP PREVIEWS** stops all local preview processes. Select VM and tap **OPEN ANDROID LINUX + CHAT** to launch the built-in Linux Terminal app when present.

For Termux, install/open it once, set `allow-external-apps=true` in `~/.termux/termux.properties`, run `termux-reload-settings`, and grant Lucifer Android’s **Run commands in Termux environment** permission.

For VM commands, configure the host/IP, SSH user, port, password, and `known_hosts` entry in Settings. For the Android Linux Terminal bridge, install `openssh-server` and `tmux` in the Debian guest, start SSH, and map a host-side port to guest port 22 in the Terminal app; use host `127.0.0.1` and that forwarded host port in Lucifer. In the Terminal app, start the shared shell with `tmux new-session -A -s lucifer`. Obtain a host-key line (for example, with `ssh-keyscan -p PORT HOST`), but **do not trust `ssh-keyscan` by itself**: compare the SHA-256 fingerprint against the VM console or another trusted channel before saving the line. Lucifer refuses VM execution if the host key is missing or changed. With this setup, both the Linux Terminal UI and Lucifer's overlay operate on that same tmux PTY; without it, the overlay cannot inspect/control the AVF guest.

## Build

Requirements: JDK 17, Android SDK 34, Android Gradle Plugin 8.3.0, Kotlin 1.9.10, and Android Studio/Gradle dependencies available.

```bash
./gradlew :composeApp:assembleDebug
```

Pure recovery/self-learning logic has a host-side harness that does not need the Android SDK:

```bash
./scripts/verify_all.sh               # every harness + every audit, one exit code

./scripts/verify_resilience_core.sh   # needs java 17+ and kotlinc on PATH (or KOTLINC=/path)
./scripts/verify_agents_core.sh       # agent ecosystem + tactician: 50 assertions
./scripts/verify_design_core.sh       # Morningstar geometry: 16 assertions
./scripts/verify_privilege_core.sh    # privilege routing + the world: 22 assertions
./scripts/verify_verification_core.sh # Lean verifier: 32 control-plane + 23 runtime/transport assertions
./scripts/verify_surface_core.sh      # surface awareness: 52 checks + call-site audit
./scripts/verify_privacy_core.sh      # egress policy: 90 checks + socket-owner audit
```

`verify_all.sh` runs all seven harnesses and all three static audits (`audit_egress.py`,
`audit_surfaces.py`, `audit_config.py`) and reports **PASS / SKIP / FAIL** separately. A harness whose
Kotlin step cannot compile because `kotlinc` is missing reports **SKIPPED**, not PASS — it did not run,
and saying otherwise is the one thing a verification script must never do. Set
`LUCIFER_REQUIRE_KOTLIN=1` (as CI does) to turn a missing toolchain into a failure.
`.github/workflows/verify.yml` runs the same command on every push.

The resilience harness compiles the `resilience/` core with 46 assertions and type-checks its Android adapter against stubs. The verifier harness compiles the verifier core, runtime and HTTP transport, runs them against a real loopback socket, and type-checks its service, controller and SSH adapter against stubs. The agents harness compiles the `agents/` and `tactician/` cores with 50 assertions and type-checks the prompt store, observation bus, signal collector, runner, service, and the heartbeat engine. Neither covers Compose UI, Gradle, or device runtime.

The repository also includes native build/deploy scripts; use them only if your target workflow needs those components. They have not been validated as part of this audit. The current audit environment has no Java runtime, so Gradle compilation and tests were not run.

## Active project layout

```text
composeApp/
  build.gradle.kts                    # Android application plugin/source configuration
  src/androidMain/AndroidManifest.xml
  src/androidMain/kotlin/com/lucifer/mobile/
    MainActivity.kt                   # Terminal, memory, skills, settings, wallet, browser, heartbeat, workflow tabs
    launcher/                         # Home launcher, chat, natural-language routing, voice
    workflows/                        # Bounded workflow plans, task persistence, and state transitions
    terminal/                         # Local, Termux PTY/overlay, VM, and Shizuku execution
    data/wallet/                      # Native EVM wallet and encrypted persistence
    data/browser/                     # Read-only HTTPS fetch/extract
    security/                         # Android Keystore-backed secret storage
    omni_bridge/                      # LLM, Kai sandbox, reasoning, and opt-in heartbeat service
    privilege/                        # Capability routing, Dhizuku bridge, local device-owner ops, ledger
    world/                            # Managed-profile discovery, the world charter, cross-profile launches
    resilience/                       # Failure classification, probes, web research, self-learning loop
    agents/                           # Prompt-file rules, agent-class parser, registry, skill composer
    agents/android/                   # Prompt store, observation bus, signal collector, tactician service
    tactician/                        # Observations, opportunity detectors, proposals, budget, tactician loop
    ui/theme/                         # Morningstar tokens, chamfer/sigil geometry, Material theme
    ui/effects/                       # Glass shards, the Fall, pulse, disintegration, backdrop
    verification/                     # Lean verifier: MCP endpoint, keys, quota, ledger, SSH transport, service
    ui/components/                    # Active Compose UI components (incl. RecoveryControlPanel, AgentsPanel, VerifierCard)
```

The repository also contains dormant `commonMain` and `kotlin.backup` prototype sources. They are not included by the active Android source-set configuration and should not be assumed to reflect the shipped app.
